# Cornerstone templates

Generated by `php bin/build-tco.php` from `config/page-templates.php`.
Do not hand-edit these files — edit the blueprint and rebuild.

Import via **Cornerstone → Manage Library → Import**.

## Read this before importing

The element hierarchy in these files is built to match Cornerstone's
Section → Row → Column → Element model, and the element `_type` values match the
names this child theme registers through `cornerstone_register_element()`.

**The outer envelope is reconstructed, not verified.** `theme.co` is blocked by
the egress policy of the environment these were built in, so the wrapper keys
and the version stamp could not be checked against a real export.

**Import `home.tco` first.** If it imports cleanly, the rest will too. If it
fails — Cornerstone's Manage Library import can fail silently, so check whether
the template actually appears — export any template from your install and send
that file back. It reveals the envelope, the version stamp, and the param
shapes, and fixing `rl_encode_tco()` in `bin/build-tco.php` is then a small,
one-pass change. Nothing else in the pipeline needs to move.

If the version stamp is the problem, `RL_TCO_VERSION` at the top of
`bin/build-tco.php` is the single place to change it. Your Cornerstone version
is shown under **WordPress → Plugins**.

## Prerequisite

The child theme must be **active** before importing, because these templates
reference its custom elements (`rl-hero`, `rl-faq`, `rl-service-grid`, and so
on). Importing into a site where the theme is inactive will produce empty
elements.

## If the import does not work

`Roberts Law → Create Pages` in the WordPress admin builds the same pages
without touching the template format at all. Each page gets a single
`[rl_page_template]` shortcode that renders the same blueprint through the same
components. Existing pages are never overwritten, and pages carrying unreviewed
copy are created as drafts.
